Mental model

It's three systems in a trench coat

Every macro tool — yours, SteelSeries, DS4Windows, AutoHotkey — is really just these three parts. Build them in order and it's never as big as it looks.

01 · Capture

Watch every key

A background hook sees each key event system-wide and decides whether it's a macro trigger.

Why it matters: to bind a macro to a key and stop it typing normally, the hook must swallow the original press.

02 · Execute

Replay the sequence

Fire the recorded events with correct timing — keystrokes, text, mouse, delays, launch apps.

This is the "software injection" part. It's the same path all three reference tools use.

03 · Interface

See & edit macros

A visual keyboard to assign binds and a timeline to record and edit — plus JSON storage and a tray toggle.

The biggest chunk of work, and the difference between "polished" and "Wootomation".

Architecture

The data model on one screen

Get these shapes right and everything else is UI. This is the backbone you'll build the app around.

Macro       = ordered list of MacroEvent

MacroEvent  ─┬─ KeyDown(key)        // press
             ├─ KeyUp(key)          // release
             ├─ Delay(ms)           // editable wait
             ├─ Text("gg ez")        // type a string
             ├─ LaunchApp(path)
             └─ MouseClick(button)

Binding     = Trigger + Macro + PlaybackMode
              Trigger      = a key   // Phase 2: key + depth threshold
              PlaybackMode = Once | WhileHeld | Toggle

Profile     = list of Bindings + optional "match this app" rule
Config      = list of Profiles      // → saved to %AppData% as JSON

Roadmap

Build it in slices, not all at once

Each phase is usable on its own. You'll have something you'd genuinely run by phase 3 — long before the GUI exists.

First step

What phase 1 actually looks like

A console app: press Caps Lock, get text typed. Runs on your Mac tonight (grant Accessibility), then the exact logic moves into WPF on your PC.

using SharpHook;
using SharpHook.Native;

var sim  = new EventSimulator();
var hook = new SimpleGlobalHook();

hook.KeyPressed += (s, e) =>
{
    if (e.Data.KeyCode == KeyCode.VcCapsLock)
    {
        e.SuppressEvent = true;              // swallow the real key (Windows)
        sim.SimulateTextEntry("gg ez");      // fire the macro
    }
};

hook.Run();   // listen for global key events

Treat it as the shape, not gospel — check SharpHook's current API for exact names. Every line here carries straight into the real app.

Before you build

Four things worth knowing

!

The keyboard can't do this itself.

The 60HE offers DKS, Mod Tap, Toggle Key, remaps and 4 onboard profiles — but those are fixed depth-rules, not recorded, timed, repeatable macros. Those must live in your app.

!

SteelSeries & DS4Windows are software too.

Same injection path as AutoHotkey. The thing you liked about them over AHK is the GUI — which is exactly what you're building.

!

Anti-cheat can flag injected input.

Global hooks + synthesized input trip some game anti-cheats. Check the ToS of any game you'd use it alongside.

!

Prototype on Mac, ship on Windows.

The engine (SharpHook) runs on your Mac for testing now. WPF is Windows-only, so the GUI and final build happen at your PC.
